## 3. Classification

HARD BLOCKER below means: *must be known before finalizing or implementing the specific policy-dependent behavior named* — it does not mean all software implementation is blocked. The corresponding foundation/mechanism for each item is separately available now under SAFE DEFAULT (S-1..S-8) or the M1-readiness list in `docs/M0_STATUS.md`.

### HARD BLOCKER — must be known before finalizing/implementing the affected workflow or policy-dependent behavior (7)

1. **HB-1** Disposal committee composition and approval authority/thresholds, if any (never invent — CLAUDE.md explicit).
2. **HB-3** Funding/project source: attribution vs. restriction. Funding/project attribution is a normal Bureau inventory attribute, not an external-project concern (Bureau FM/Procurement Manuals maintain funding/project-attributed records as a matter of course). The unresolved question is narrower than the label once suggested: does funding/project source merely attribute/report on stock, or does it also **restrict** ATP eligibility, commitment-to-funding matching, cross-source stock substitutability, final balance-projection grouping/uniqueness semantics, and any restrictive DB constraint/posting validation keyed on funding/project? Does **not** block defining `inventory_entries`/`inventory_commitments` — their `funding_source_id`/`project_id` columns can exist now as nullable, attribution-capable fields (`DATA_MODEL.md`). Nullable is for "not applicable / not yet known," not "optional to record": any workflow that captures a known funding/project source at posting time must still populate the column even though it is not yet a restriction — because posted ledger entries are immutable (INV-002), a source left unrecorded when it was actually known cannot be reliably added later. **2026-09-24 evidence pass:** targeted web and Drive research found no evidence resolving the attribution-vs-restriction question — every reviewed Bureau operational document (FM Manual, Procurement Manuals, Operational Handbook, internal-audit evidence) discusses fund flow/reporting and fiduciary segregation of duties, never physical-stock segregation across sources. HB-3 remains fully OPEN; only a direct Finance/BoFED clarification (not a document search) can resolve it.
3. **HB-4** Consolidated approval/signature authority matrix (real Bureau titles/authority levels and thresholds, if any, per transaction type).
4. **HB-5** Stock-adjustment/variance approval authority/thresholds, if any.
5. **HB-6** Warehouse-transfer dispatch authorization and receipt-discrepancy resolution authority.
6. **HB-7** Period-close certifying authority (who signs/certifies closing balances).
7. **HB-8** GRN (Model 19) vs. Stores Receipt Voucher (SRV) relationship — same document, sequential documents, alternative terminology, or documents used for different functions (`OFFICIAL_PROCESS_MAPPING.md` §"terminology conflict"). This is not a conflict between separate documents of unclear standing: both the Bureau FM Manual (GRN/Model 19) and the Bureau Procurement Manual (inspection/acceptance then SRV) are Class BOE — Bureau operational evidence — so the open question is purely operational: what is the actual relationship between these two Bureau-documented steps? **Evidence narrowed (2026-09-24, DRDIP-004/DRDIP-006):** two further Bureau documents (the updated FM Manual and the 2025 Community Procurement Manual) were checked and, like DRDIP-001, use only "Goods Received Note/Receipt Note (GRN/Model 19)" with zero occurrences of "Stores Receipt Voucher"/"SRV" — consistent with a hypothesis that GRN (FM/payment-control side) and SRV (procurement-manual/inspection side, per DRDIP-002) are two different documents used at different process stages, or serve different functions, rather than a manual inconsistency. This is a hypothesis strengthened by repetition across independent Bureau documents, not a confirmation. Keep OPEN until the actual forms/process owner confirms whether GRN/Model 19 and SRV are: the same document; separate sequential documents; alternative terminology for the same step; or documents used for different functions. Still a HARD BLOCKER.

**HB-2** (stock-vs-fixed-asset classification) is no longer listed here — see "CURRENT BUREAU OPERATIONAL RULE" immediately below.

The current regional manuals/forms/authority confirmations requested in `M0_SOURCE_REQUEST.md` are the primary evidence expected to resolve these seven blockers; some (e.g. HB-3's attribution-vs-restriction question) may require separate Finance/BoFED clarification beyond the manuals themselves.

### CURRENT BUREAU OPERATIONAL RULE — subject to supersession (1)

1. **HB-2 → resolved to Bureau operational baseline.** Stock-vs-fixed-asset classification criteria: an item leaves ordinary warehouse-stock handling for fixed-asset custody when **useful life > 1 year AND value ≥ Birr 2,000** — the Bureau's own current FM Manual criterion (DRDIP-004, corroborated by the register-field structure in DRDIP-001). This is Class BOE (Bureau operational evidence), demonstrably part of the Bureau's own current operational practice, not merely a project reference — so HB-2 no longer remains a hard blocker solely because a separate regional manual restating the same criterion has not yet been found. **Use this as the current BoA-IMS system baseline** for the item-master stock-vs-asset control flag. This is **not a final, immune ruling**: per the evidence hierarchy, a verified current Somali Region/BoFED controlling manual or directive (Class A) that is later found and actually conflicts with this figure supersedes it automatically; the change would then be recorded here and, if it affects already-seeded item-master data, in an ADR. Supersession does **not** retroactively alter already-posted `inventory_transactions`/`inventory_entries` for items already transacted under the prior classification — those are immutable once posted (INV-002); any required catch-up (e.g. an item that should have followed the asset-custody-handover path instead of ordinary Issue, or vice versa) is a standard reversal/compensating correction (INV-003), subject to the same dependency/closed-period rules as any other posted-history correction, and is itself recorded via ADR — never a silent item-master flag flip. Do not treat this baseline as more than what it is — a current Bureau operational rule, not a verified Class A regional legal instrument.
